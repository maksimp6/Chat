# Нативный лаунчер (android-native)

Лаунчер на C (`NativeActivity`), собирается без Gradle и без Java-кода. Сборка идёт на телефоне (Termux).

## Структура

| Путь | Назначение |
|---|---|
| `src/launcher.c` | исходник лаунчера (C11) |
| `AndroidManifest.xml` | манифест, `targetSdk` 29 (подпись v1) |
| `tools/stages/compile.sh` | стадия compile: `clang` → `.so` |
| `tools/stages/link.sh` | стадия link: `aapt2 link` → `base.apk` |
| `tools/stages/sign.sh` | стадия sign: `sign_v1.py` → APK ровно 1 МиБ |
| `tools/build-full.sh` | оркестратор стадий, кэш по времени изменения файлов |
| `tools/build-native.c` | точка входа: если APK актуален, выходит сразу |
| `tools/build-serverd.c` | dev-сервер: фоновая пересборка, сокет `~/.build-native.sock` |
| `tools/build-ctl.c` | клиент сервера: `ping`, `status`, `build`, `metrics` |
| `tools/bench.sh` | бенчмарк стадий против бюджетов |
| `tools/test.sh` | тесты: C11 pedantic, размер и подпись APK, `fastcheck` |
| `tools/perf-budget.env` | бюджеты времени стадий |
| `RESULTS.md` | замеры и выводы |

## Рабочий цикл

1. Правка `src/launcher.c` или `AndroidManifest.xml`.
2. Запустить dev-сервер один раз: `cd android-native && (nohup ./tools/build-serverd "$PWD" >$HOME/serverd.log 2>&1 &)`. Он пересоберёт APK сам при каждом изменении.
3. Получить готовый APK: `./tools/build-ctl build` (ответ за 1–2 мс, если сборка уже готова). Или без сервера: `./tools/build-native`.
4. Проверить: `bash tools/test.sh` и `bash tools/bench.sh`.
5. Установить: `su -c "pm install -r $PWD/build/native.apk"`.
6. Метрики: `./tools/build-ctl metrics`.

## Перед коммитом (обязательно)

- `bash tools/test.sh` — все проверки должны пройти (сейчас 11 из 11).
- `bash tools/bench.sh` — все стадии в пределах бюджета (`perf-budget.env`).
- Если меняли замеры — обновить `RESULTS.md`.

## Требования к производительности

Бюджеты хранятся в `tools/perf-budget.env` (мс):

| Что | Бюджет | Текущее |
|---|---|---|
| compile | 800 | ~607 |
| link | 300 | ~195 |
| sign | 900 | ~482 |
| orchestrator (кэш) | 60 | ~54 |
| fastcheck (`build-native`, APK свежий) | 25 | ~13 |
| dev-сервер, ответ на `build` при готовом APK | 2 | ~0.2 |

Если стадия превышает бюджет, `bench.sh` возвращает код ошибки. Бюджет меняется только вместе с записью в `RESULTS.md`.

## Ограничения

- Компиляция через `clang` не опускается ниже ~180 мс: это запуск процесса.
- Шим на `libclang-cpp` (`tools/clang-warm/`) не завершён: не находятся системные заголовки внутри процесса.
- Подпись v1 использует `openssl cms`; это отдельная внешняя зависимость.
- Тесты проверяют стандарт C11 и корректность APK, но не запуск на устройстве.

## CI

GitHub Actions для этой папки не настроены. Сборка и тесты выполняются на телефоне. Добавление workflow в CI требует отдельного решения.

## Правила изменения кода при ограничениях

Применяются, когда нужно уменьшить размер или время, но сохранить поведение.

1. Поведение не меняется: выход программы и код возврата до и после изменения должны совпадать. Проверяется запуском обоих вариантов на устройстве, а не только сборкой.
2. Размер уменьшается только техниками, которые не меняют вычисления: более короткие инструкции, адресация относительно PC (`adr` вместо пары `movz`/`movk`), выравнивание. Удаление строк, вывода или `exit` запрещено, если это меняет результат.
3. Каждое изменение сопровождается замером: размер файла до и после, время сборки по `tools/bench.sh`.
4. Если сокращение требует перекрытия полей заголовков или других нестандартных трюков, оно не принимается без отдельного обсуждения: такой файл ломается без понятного сообщения об ошибке.
5. Результат фиксируется в `RESULTS.md` с числами и командой проверки.
