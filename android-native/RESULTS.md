# Результаты замеров нативной сборки (Redmi 9, Termux)

Все времена — wall time, мс. Если не указано иное, лучший из нескольких прогонов.

## Запуск процессов
| Что | мс |
|---|---|
| Пустая программа на C | 12–17 |
| `bash -c exit 0` | 15 |
| `clang --version` | 185 |
| `clang -c` пустого файла `int x;` | 181 |
| `clang -c` с тремя NDK-заголовками | 255 |

| `clang -shared launcher.c` (компиляция + линковка) | 293–308 |

## Артефакты
- `native.apk` ровно 1 048 576 байт, `unzip -t` без ошибок, v1-подпись (`CERT.RSA`), `pm install -r` — `Success`.
- Тесты `tools/test.sh`: 11 из 11 проходят. Исходник `launcher.c` и host-утилиты компилируются с `-std=c11 -pedantic -Wall -Wextra -Werror`.

## Шим на libclang-cpp (спайк, не завершён)
- `tools/clang-warm/shim.cpp` собирается (`clang++ ... -lclang-cpp -lLLVM`) и запускается.
- Путь `android/log.h` находится (после исправления triple на `aarch64-unknown-linux-android26`).
- Падение: `stdarg.h` не найден, хотя файл есть в `usr/lib/clang/21/include`. Пути поиска, переданные флагами `-internal-isystem` и через `HeaderSearchOptions::AddPath`, не помогли.
- Первый вызов до падения: 76 мс (включая инициализацию компилятора).
- Тёплая компиляция пока не измерена, выигрыш от предзагрузки `clang` не подтверждён.
- Следующий шаг: в шиме вывести фактический список путей поиска (`HeaderSearch`) и сверить с ожидаемым.

## Ограничения
- Ниже 100 мс компиляция `launcher.c` через `clang` не выходит: сам запуск стоит около 180 мс.
- `tcc` не разбирает NDK-заголовки (`enum : uint32_t` в `input.h`).
- Подпись v1 через `openssl cms` занимает около 300 мс, и это отдельная стадия.
