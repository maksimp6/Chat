## Уровень 1 — рабочее ядро

### Цель и ближайший результат [ПРИНЯТО]
1. **Первый настоящий запуск Logos:** открыть приложение → написать сообщение → получить ответ модели → вызвать инструмент → увидеть результат. Не зелёный CI, не отчёт [25, 61].
2. **Временное правило:** «Никаких новых архитектурных подсистем, пока не проверен первый полноценный пользовательский диалог с приложением». Исключение — исправления, без которых диалог технически невозможен или небезопасен [61].
3. **План дня 18.10:** бизнес, GitHub, 3D-печать, телефон-сервер, ВК/Дзен — через гитхаб и пайплайны, «чтобы мозг не таял от нагрузки» [21]. Главный принцип: «меньше планирования, больше завершённых задач» [25]. Pomodoro отклонён.

### Принятые решения [ПРИНЯТО]
1. **Роль Logos — координатор моделей**, не третий собеседник: распределяет задачи, проверяет результаты, снимает с человека роль курьера [33, 35].
2. **Атрибуция:** Автор / Источник / Исполнитель — разные понятия; к каждому результату — доказательство выполнения (ID вызова, SHA, ссылка на артефакт). «Нельзя присваивать verified только потому, что модель сама так написала» [39].
3. **Память:** «Отсутствие памяти — не ошибка. Выдуманное воспоминание — ошибка». Агент обязан различать доказанный факт, предположение и собственную фантазию [49, 51].
4. **Цикл действий:** OBSERVE → VERIFY → DECIDE → DO → VERIFY RESULT. «Fact-check перед любым Do». Не выдавать гипотезу за диагноз; необратимое — только с разрешения; «никаких действий на основании одного Offline, HTTP 200, Exit 0 или зелёного CI» [63].
5. **Судить утверждения, а не личность агента:** ошибка → исправление, не наказание [59].
6. **Статусы утверждений:** ДОКАЗАНО / ГИПОТЕЗА / НЕИЗВЕСТНО [59]; для этого конспекта добавлены ЗАФИКСИРОВАНО / ПРИНЯТО / ОПРОВЕРГНУТО.
7. **Инструкцию для ChatGPT писать самим,** не брать версию GigaChat [71→73]; включить пример «закон противоречит жизни» (РКН) и рай/ад [73]. → версия ещё не написана.
8. **Не ждать идеала:** «правила нулевой идеальности» [75], «законодатели не служат» — система служит целям пользователя, не правилам ради правил [77].

### Рабочие принципы [ЗАФИКСИРОВАНО]
- **Триада:** Каин/Закон (правила ради правил, бюрократия) · Логос/Суть (смысл, свобода) · Реальность (безжалостный арбитр) [1].
- **Инженерные принципы:** Каин предупреждает — не превращай правила в самоцель; Логос создаёт — самое простое решение, которое действительно выполняет задачу; Реальность проверяет — измеряй скорость, стоимость, работоспособность [7].
- **Формула:** Замысел + Исполнение + Проверка = Результат [7].
- **Контракт агентов:** каждый агент получает отдельную задачу и отвечает за её завершение; никакого merge, опасных действий с устройствами или запуска печати без разрешения; результат подтверждается работающим сервисом, измерением или физическим устройством [25].
- **Поведение ответов:** не заканчивать каждое сообщение вопросом; не предлагать выбор, когда не просили; не превращать общение в управление меню [67].
- **30 секунд — измеримый бюджет, не цифра на инфографике:** превышение даёт POLICY_PASS, но фактические ошибки остаются видимыми [7]. (Конфликт с Issue #1365 — см. ниже.)
