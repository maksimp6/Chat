# Инструкции разработки

## Публикация и тестирование

Если пользователь дал команду разрабатывать или изменять код и не дал отдельной команды об ином порядке:

- **Единственный маршрут публикации изменений кода: прямой `push` в `develop`. Не создавать промежуточные ветки и PR, не предлагать PR как альтернативу.**
- Команды «дальше», «продолжай», «исправь», «чисти код» и кнопки продолжения означают продолжение работы по этому маршруту, а не разрешение менять его.
- Не выполнять merge PR вместо прямого push. Если прямой push технически заблокирован, сообщить блокер, а не обходить его через PR.
- Не запускать никакие тесты кода, в том числе локальные быстрые, smoke-, unit-, integration-, E2E-тесты и тестовые сборки.
- Не инициировать тестовые workflow или иные проверки кода под видом локальной диагностики.
- Если пользователь отдельно поручил тестирование, выполнять только явно разрешённые проверки.
- Не выдавать отсутствие тестов за успешную проверку; указывать `NOT_RUN`.
- Не выполнять force-push, не менять защиту веток и не сливать изменения в `master` без отдельной команды.

Эти правила не отменяют обязательные ограничения безопасности и действуют только для команд на разработку. При прямой отдельной команде пользователя применяется оговорённое исключение.

## Только GitHub Runner для тестов

- Запуск тестов кода разрешён исключительно внутри задания GitHub Actions runner; на локальном устройстве запуск должен завершаться ошибкой.
- Для Python pytest и импорта пакета tests проверяются признаки задания: GITHUB_ACTIONS=true, CI=true, GITHUB_RUN_ID, RUNNER_NAME, RUNNER_TEMP.
- Эти переменные среды не являются криптографической аттестацией runner: не считать их защитой от намеренного обхода.
- Запрещено подменять переменные среды ради обхода локального запрета.
- Данное правило само по себе не инициирует тестовые задания при разработке; тесты выполняются только по отдельной команде пользователя.
