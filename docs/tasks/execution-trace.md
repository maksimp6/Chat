# Alice Pro: единый Execution Trace и metadata

## Цель
Реализовать современную систему трассировки выполнения `/api/chat`.
Нужно видеть полный жизненный цикл запроса:
`user request → Yandex Responses → function_call → local tool/MCP → tool result → следующий Responses → final response`
При этом обычный ответ пользователю должен оставаться чистым.

## 1. ExecutionTrace
Создать/использовать централизованный объект `ExecutionTrace`.
Он должен собирать:
- исходный `request` payload;
- все сырые JSON-ответы Yandex Responses API (`responses`);
- события выполнения в фактическом порядке (`events`);
- все function/tool calls (`tool_calls`);
- `errors`, timestamps и итоговые `timings`.

Сырые Responses API не пересобирать вручную. Сохранять исходный сетевой JSON целиком.

## 2. trace_id и metadata
Для каждого выполнения создавать уникальный `trace_id`.
При отправке запросов к Yandex Responses API (`/v1/responses`) использовать встроенный объект `metadata` для сквозной корреляции.
**Важно:** Учитывать ограничение Yandex API: все значения внутри объекта `metadata` должны быть строго строкового типа (string), без вложенных объектов, массивов и циклических ссылок. Полный ExecutionTrace внутрь metadata не помещать.

## 3. Local tools и MCP
При каждом вызове инструмента создавать событие. Это должно работать одинаково для локальных тулов, MCP-серверов и будущих автономных агентов. Не плодить изолированные трейсеры.

## 4. Порядок событий (Timeline)
Сохранять хронологический порядок. Коллекция `events` служит основным линейным таймлайном, а `responses` и `tool_calls` — структурированными выборками.

## 5. API response
Формат ответа `/api/chat` должен включать новый ключ `"trace"`, не ломая существующие поля (`reply`, `usage`, `timings`, `cost`).

## 6. Безопасность и Sanitization
Перед отправкой `trace` на frontend или записью в логи удалять/маскировать API-ключи, токены авторизации и чувствительные заголовки.

## 7. Frontend UI
В сообщении ассистента отображать сворачиваемый блок `🔧 Технические данные`, внутри рендерить данные trace. Текст основного сообщения остаётся чистым.

## 8. Совместимость
Перед внесением изменений изучить `yandex_client.py`, `mcp_routes.py`, `tool_registry.py`, `logger.py`, `db.py`. Не создавать дублирующих сущностей.
