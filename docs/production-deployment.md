# Эксплуатация и восстановление Logos

## Действующий маршрут Redmi 9

Веб-приложение обновляет существующий GitHub runner при доставке изменений
в `develop`. Он использует controller с сохранением журнала и откатом кода
при неудачной готовности.

- [Server runbook](redmi-app-server.md): процесс, LFS, launcher, readiness и Wi-Fi.
- [Обновление раннером](setup/redmi9-auto-update.md): порядок обновления и receipts.
- [Kristall](database.md): один writer, backup/restore и сохранность данных.

Фактический revision процесса, PID и версия загруженного UI требуют собственных
доказательств. Ответ health или успешная job не подтверждают весь сценарий чата.

## Доступ

Действует [shared local access](security/github-login.md): интерфейс открывают
напрямую, старые настройки входа не включают аутентификацию.
Сетевую доступность и режим публикации определяет конкретное развёртывание.
Наличие этого документа не подтверждает публичный DNS/TLS или доступ со второго
телефона.

## Восстановление

Controller возвращает предыдущий код при неудачном startup/readiness;
такой исход не считается успешной доставкой запрошенного обновления.
Журнал не подменяется автоматически резервной копией.

Для восстановления данных используйте [контракт backup/restore](database.md#backup-and-restore)
и соответствующее поручение владельца. Сохраняйте путь журнала и ключ шифрования.

Прежний VPS workflow выпуска/отката и token-prefixed схема доступа удалены
из действующей инструкции. Работы по Cloud.ru остаются отдельной интеграцией:
[Container Apps](cloudru-container-apps.md) и [облачный контур](integrations/cloud-provider-foundation.md).
Их наличие не доказывает принятый production cutover.
