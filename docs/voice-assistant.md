# Voice assistant

Issue #105 verifies and restores the end-to-end voice assistant path.

## Pipeline

`microphone -> browser recording -> /api/voice/audio -> SpeechKit STT -> existing Alice chat pipeline -> SpeechKit TTS -> browser playback`

The browser prefers OggOpus recording when the browser exposes it. A PCM/WAV fallback is used otherwise. SpeechKit synchronous recognition is limited to 1 MiB and 30 seconds, so the server rejects larger audio payloads.

## API

- `POST /api/voice/session` creates an isolated voice session.
- `POST /api/voice/audio?session_id=...` uploads recorded audio.
- `GET /api/voice/events?session_id=...` streams lifecycle/result events as SSE.
- `GET /api/voice/output?session_id=...` returns synthesized OggOpus audio.
- `POST /api/voice/close` starts STT → chat → TTS processing.

## Authentication

The backend accepts either server-side `YANDEX_API_KEY` or `YANDEX_IAM_TOKEN`. The optional `YANDEX_PROJECT_ID`/folder ID is passed to SpeechKit when configured. Credentials are never sent to the browser.

Yandex documents IAM-token authentication with `Authorization: Bearer` and service-account API-key authentication with `Authorization: Api-Key`.

## Response modes

- `text`: recognize and return text only.
- `audio`: recognize, generate the chat response, synthesize audio.
- `both`: return both text and synthesized audio.

Voice model identifiers from `VOICE_MODELS` are not passed to the text chat provider. The voice session may carry the selected voice model for UI compatibility, while the response is generated by `ALICE_VOICE_CHAT_MODEL` or `aliceai-llm`.

## Security boundaries

Voice session IDs are random UUID-derived values. A session is scoped to the owner and, when supplied, to the conversation owner. Audio is kept in memory and automatically expires after the session TTL. Provider credentials remain server-side.

## Known scope

This implementation is a reliable request/response voice assistant, not a bidirectional low-latency SpeechKit realtime session. Streaming recognition and streaming TTS can be introduced later through SpeechKit API v2/v3 without changing the public browser session contract. Yandex documents streaming recognition separately from the synchronous v1 API.
