# Work Map по `trips.db`: статус и границы данных

## Статус

Статус сценария в Alice Pro — `research`. Был проверен отдельный пакет Work Map на пользовательской копии SQLite-базы. Этот разовый запуск не означает, что Alice Pro уже умеет искать `trips.db`, читать его через собственные коннекторы или собирать карту из чата. Реальная интеграция в Alice Pro пока не реализована.

Результат частной сборки остаётся пользовательским артефактом. В этот репозиторий не входят база, карта или её исходные маршруты.

## Что проверено в отдельной сборке

- SQLite-база открывалась для анализа без изменения исходного файла; проверка целостности прошла.
- Исправлена ошибка импорта `urllib.parse` в генераторе и добавлено исключение поездок с признаком удаления.
- Отображение треков сохраняет исходные границы сегментов и разрывы по дате/длительным паузам. Прыжки между сегментами не включаются в расстояние.
- У генератора есть фильтр рабочего времени. Часовой пояс, расписание и порог разрыва должны стать явными настройками пользователя, а не настройками по умолчанию для всех.
- Привязка фотографий работает как best effort: непривязанные фото нельзя выдавать за подтверждённые остановки или поездки.
- Точки/waypoints не доказывают факт посещения. Это можно утверждать только при наличии явного статуса посещения.

Точные количества записей и личное расписание в публичной документации не фиксируются.

## Целевой сценарий для Alice Pro

1. Пользователь выбирает источник `trips.db` и пакет генератора из подключённых хранилищ.
2. Alice Pro получает только разрешённые файлы через provider-neutral storage capability (#340), в рамках владельца и runtime.
3. Перед обработкой создаётся согласованный временный снимок SQLite. Источник остаётся неизменным; учитываются возможные `-wal` и `-shm` файлы.
4. Генератор проверяет схему и целостность, игнорирует удалённые поездки и использует явно выбранные часовой пояс, рабочие часы и параметры разрывов.
5. Карта сохраняется в приватную папку, выбранную пользователем. Перед изменением общего доступа или публикацией требуется отдельное подтверждение.
6. Временные копии очищаются после успешного экспорта или ошибки.

Это целевое описание, а не утверждение о текущих возможностях. Подробности провайдеров и статусы их поддержки относятся к каталогу интеграций (#467).

## Безопасность и трассировка

Данные маршрутов чувствительны. Не коммитить в Git, issue, тестовые логи или Execution Trace:

- `trips.db`, файлы `-wal` / `-shm` и реальные дампы;
- координаты, полилинии, временные метки маршрутов, фотографии и их метаданные;
- экспортированный `data.json`, готовый ZIP с маршрутами, личные ID/ссылки файлов;
- credentials, OAuth-токены и cookies.

В Trace допустимы только безопасные операционные сведения: этап, статус, длительность, код ошибки и несекретный идентификатор операции. Содержимое строк БД и координаты туда не записываются. Исходный файл никогда не меняется; чтение/запись проходят через storage/tool boundaries Alice Pro, а runtime-ресурсы — через RuntimeDispatcher (#350).

В CI используются только синтетические базы и фиктивные изображения. Синтетические координаты должны быть вымышленными и не выводиться в логи.

## Проверки перед статусом `supported`

- Fixture содержит активную и удалённую поездки, несколько сегментов, смену даты, длительный разрыв, посещённую и непосещённую waypoint-точки, отсутствующие привязки фотографий.
- Тест подтверждает, что удалённая поездка не попадает в карту, разрывы не учитываются как расстояние, а исходная БД остаётся неизменной.
- Часовой пояс, рабочие часы и пороги разрывов задаются настройками, а не захардкожены для одного пользователя.
- Интеграционный тест проходит через существующий storage/tool/runtime контракт; проверяется owner/runtime scope.
- Trace и сообщения об ошибках не содержат координат, содержимого БД, токенов или приватных ссылок.
- Проверено сохранение результата в выбранную папку без автоматической публикации или изменения sharing.
