# Правила веток

`develop` — интеграционная ветка; `master` — личная ветка владельца.
Маршрут работы задают прямое поручение и [AGENTS.md](../../AGENTS.md).

Устаревшие предложения настройки rulesets с проверками PostgreSQL, Android APK
и удалёнными CI jobs убраны. Этот документ не содержит payload для применения
и не подтверждает текущие настройки GitHub.

Если задача требует проверки защиты веток, сначала прочитайте фактические
настройки. Изменять их или выполнять продвижение в `master` можно только
по отдельной команде владельца.

## Recover readiness after resolving threads

После изменения review threads или HEAD перечитайте состояние PR и результаты
для точного SHA. Прежний workflow readiness snapshot больше не является
действующим маршрутом проверки. Не запускайте отсутствующую job и не выдавайте
старый результат за проверку нового HEAD.

См. [интеграцию](develop-integration.md).
