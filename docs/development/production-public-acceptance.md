# Подтверждение доступа к приложению

Текущий режим описан в [shared local access](../security/github-login.md).
Ожидание обязательного 401 от корня и проверка прежнего токенового входа
исключены из действующей приёмки. Старый `production_public_probe.py` с таким
ожиданием не является проверкой текущего режима доступа.

Для порученной проверки зафиксируйте:
- точный адрес и идентичность устройства/клиента;
- `runtime_revision`, PID и версию загруженного UI;
- загрузку интерфейса и нужных статических ресурсов;
- видимый результат согласованного пользовательского сценария;
- отдельный запрос со второго устройства, если требуется межклиентский доступ.

Проверка телефоном собственного Wi-Fi адреса имеет область
`server_wifi_address`; она не устанавливает `external_peer_verified`.
См. [server runbook](../redmi-app-server.md#wi-fi-readiness).

HTTP 200 и готовность процесса не подтверждают ответ модели или работу MCP.
Провайдерские вызовы выполняйте только в разрешённых владельцем границах.
Тесты кода — только по отдельному поручению внутри runner, согласно
[AGENTS.md](../../AGENTS.md). Отсутствие проверки — `NOT_RUN`.

Для публичного развёртывания отдельно подтвердите согласованные DNS/TLS,
маршрутизацию и видимый результат из целевого клиента. Этот документ сам
не запускает проверок, не меняет доступ и не подтверждает cutover.
