# Неудобства интерфейса Logos: статический поиск, 2026-10-26

**Статус: PARTIAL.** Пункты найдены чтением кода фронтенда (`static/`) и текстов ошибок API. Интерфейс в браузере и на устройстве не запускался, тесты не запускались (`NOT_RUN`). Каждый пункт — гипотеза о том, как пользователь столкнётся с проблемой; сценарии нужно подтвердить на устройстве.

Найдено **16** пунктов. Отчёт не полный: модули, которые не просмотрены, перечислены в конце.

## Как искали

1. Поиск по шаблонам в `static/`: `alert`, `prompt`, `confirm`, `location.reload`, пустые `catch`, таймауты свыше 5 с, `console.error` без пользовательского сообщения, `innerHTML`.
2. Чтение пути отправки сообщения (`static/chat.js`, функции `sendTurn`, `loadHistory`, `pollImageOperation`) и управления диалогами (`static/sidebar.js`).
3. Сопоставление текстов ошибок: что возвращает API (`app.py`, `chat/mcp_routes.py`, `remote_runtime/environment_routes.py`) и что выводит интерфейс.
4. Проверка кнопок и размеров касания в `static/style.css`.

Критерий включения: путь к файлу и строке, описание того, что видит пользователь, и критерий исправления.

## Находки и критерии исправления

### Тексты ошибок

**Критерии исправления:**

- Пользователь видит фразу на русском: что произошло и что сделать. Машинные коды не показываются.
- Словарь кодов ошибок ведётся в одном месте и покрывает все ответы API, которые выводятся в интерфейсе.
- Технические детали (имена исключений, тексты библиотек) не выводятся в интерфейс, а пишутся в лог.

**Проверка:** для каждого кода из словаря — тест, что сообщение на русском и содержит действие. Отдельный тест, что в ответе API нет имени исключения.

**276. Пользователь видит коды ошибок вместо текста.** `static/environments.js:28-29`, `:67-68`, `:140-155`. `throw new Error(data.error)` выводит `environment_not_running`, `environment_not_found`. Та же схема в чате: `static/chat.js:1013-1015` показывает `⚠️ Ошибка: conversation_not_found`. Риск средний.

**277. Причина скрыта, действовать нельзя.** `app.py:442-444`. Проверка SSH возвращает `ssh_connection_test_failed`, хотя `remote_runtime/ssh.py` знает причину: нет `known_hosts`, пользователь не в allowlist. Исправление: передавать код причины из исключения. Риск средний.

**278. Английский текст и имена исключений в интерфейсе.** `chat/mcp_routes.py:552-555` выводит `NoActiveCredentialError: No active yandex provider credential`. Пользователь без ключа провайдера получает имя исключения, а не инструкцию. `static/chat.js:1035` выводит `error.message` браузера (`The operation was aborted due to timeout`, `Failed to fetch`). `static/chat.js:864`: «image generation timed out». Связано с п. 30 отчёта по коду (утечка внутренних сообщений). Риск средний.

**291. Технический текст в ответах для пользователя.** `chat/mcp_routes.py:485`: «Responses API завершил tool-call цепочку без текстового ответа». Пользователь не понимает, что делать. Риск низкий.

### Отправка и ожидание ответа

**Критерии исправления:**

- Любое действие пользователя даёт видимый результат: отправка, отказ, причина.
- Длительная операция показывает прогресс и предлагает остановку.
- Кнопка отправки блокируется, пока идёт предыдущий ответ, и это видно.

**Проверка:** сценарий на устройстве: отправить два сообщения подряд, остановить длинный ответ, убедиться, что текст не теряется.

**279. Отправка молча не работает, пока идёт ответ.** `static/chat.js:919-921`. Функция возвращает управление без сообщения. Кнопка не блокируется (`sendBtn.disabled` нигде не используется). Текст остаётся в поле, причина не видна. Риск средний.

**280. Ответ нельзя остановить.** `static/chat.js:992`: таймаут 300 000 мс (5 минут). Кнопки «Стоп» нет: поиск по `stop|cancel|Отмен|Стоп` в `chat.js` ничего не находит. Сервер продолжает работу после обрыва (п. 236 отчёта по коду: клиент отваливается, сервер доделывает инструменты, «Повторить» запускает цепочку заново). Риск высокий.

**287. Текст не возвращается в поле при ошибке сервера.** `static/chat.js:1013-1015`. Текст пользователя возвращается в поле только при сетевой ошибке (`:1034`). При ошибке сервера остаётся пузырь с кнопкой «Повторить», но чтобы исправить текст, его надо набирать заново. Риск низкий-средний.

**288. Enter отправляет незаконченное сообщение на телефоне.** `static/chat.js:1044-1051`. Enter на виртуальной клавиатуре отправляет сообщение, отменить нельзя. Риск низкий-средний.

**289. Ошибки о фото мешают чату.** `static/chat.js:811`, `:815`, `:823`. Сообщения о неверном файле добавляются пузырями в ленту чата, а не у поля выбора фото, и копятся. Риск низкий.

### Загрузка данных и повтор

**Критерии исправления:**

- Ошибка загрузки не закрывает весь экран: остаётся содержимое и кнопка «Повторить».
- Ошибка не подменяет причину: сеть не называется ошибкой сервера и наоборот.

**Проверка:** отключить сеть на устройстве, открыть диалог, нажать «Повторить» после восстановления связи.

**284. Ошибка загрузки истории закрывает весь чат.** `static/chat.js:724-731`. Выводится «Ошибка сети: HTTP 404», кнопки «Повторить» нет. Выход — перезагрузка страницы. Риск средний.

**283. Неверная причина в тосте.** `static/sidebar.js:86-88`, `:116-117`. При HTTP 404 или 500 показывается «Ошибка сети при удалении», хотя сеть работает. Fallback `Network response was not ok` тоже неверен. Риск низкий-средний.

**285. Кнопка трассы молчит или сдаётся.** `static/chat.js:639-642`: если Trace Viewer не загружен, кнопка ничего не делает, пишется только `console.error`. `static/chat.js:653-656`: при ошибке загрузки текст «🔍 Трасса недоступна» без причины и без повтора. Риск низкий-средний.

**286. Категории инструментов не загружаются повторно.** `static/settings/settings_modal.js:160-162`. Ошибка выводится как «Ошибка загрузки категорий», причина не показана, повтора нет, нужно закрыть и открыть окно. Риск низкий-средний.

### Управление диалогами и нативные диалоги

**Критерии исправления:**

- Каждое действие (переименовать, удалить) доступно на сенсорном экране без двойного клика.
- Подтверждение и ввод не зависят от нативных диалогов WebView, которые могут не работать.

**Проверка:** на устройстве (Android WebView): переименовать диалог, удалить диалог, проверить, что действие произошло или показано сообщение.

**281. Переименовать диалог на телефоне неочевидно.** `static/sidebar.js:75-79`. Единственный путь — двойной клик (`dblclick`). Другого пути (меню, долгое нажатие) в `static/` нет. На сенсорном экране двойное касание обычно масштабирует страницу, и `dblclick` может не возникнуть. Риск высокий (главная платформа — Android WebView).

**282. Нативные диалоги в WebView могут молча не работать.** `static/sidebar.js:79`, `:112`, `static/file_manager.js:210`, `:498`, `static/memory_panel.js:94`, `static/environments.js:132`, `static/settings/settings_mcp.js:121`, `static/settings/settings_modal.js:597`. `prompt()` и `confirm()` в WebView без обработчика `onJsPrompt` / `onJsConfirm` возвращают `null` / `false`. Тогда переименование и удаление не происходят, без сообщения. В репозитории обработчика нет: нужна проверка Android-клиента. Риск средний (требует проверки).
