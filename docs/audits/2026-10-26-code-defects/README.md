## Находки и критерии исправления

### P1. Процессы, таймауты и буферы

**Критерии исправления:**

- При таймауте останавливается вся группа процессов (`start_new_session` и `os.killpg`), потомки не остаются.
- Вывод процесса всегда `str` (декодирование с `errors="replace"`), объём ограничен до чтения в память.
- Обработчик, остановленный по таймауту, не запускается повторно параллельно с зависшим экземпляром.
- Дескрипторы и потоки закрываются на пути ошибки.

**Проверка:** Регрессионный тест: команда с дочерним `sleep` после таймаута не оставляет процессов; вывод с неполным UTF-8 сериализуется в JSON. Статус проверки: `NOT_RUN`.

1. **Орфан-процессы после timeout** — `sessions/runtime.py:101-109`, `tool_providers/filesystem.py:717-723`.
   `subprocess.run(shell=True, timeout=...)` на POSIX убивает только `sh`. Дочерние процессы продолжают работать. Эталон решения уже есть: `scripts/redmi_app_autoupdate.py:191-202` (`start_new_session` + `os.killpg`).
   Исправление: `start_new_session=True`, при timeout `os.killpg`.

2. **Байтовый вывод при timeout** — `sessions/runtime.py:119-126`.
   `TimeoutExpired.stdout/stderr` приходят как `bytes`, даже при `text=True` (поведение CPython, не проверено запуском). Срез `[:max_output_bytes]` может разрезать UTF-8-символ, а `bytes` в ответе ломает JSON-сериализацию.
   Исправление: декодировать с `errors="replace"`.
   _Статус: исправлено, коммит `4251139`. Проверка: `NOT_RUN`._

54. **Утечка дескриптора** — `secret_store/files.py:35-40`. Если `os.fchmod` бросит исключение, `fd` из `mkstemp` не закрывается: `fdopen` вызывается после. Низкий риск.

65. **Таймаут не убивает потомков** — `tool_providers/runtime_tools.py:111-121`. Та же проблема, что в п. 1: убивается только `bash`. Нужна новая сессия и `os.killpg`.

71. **Запись runtime без лимита** — `runtime/dispatcher.py:102-108`. Нет ограничения размера, запись не атомарна. Runtime может занять весь диск, при сбое остаётся частичный файл. Средний-низкий риск.

77. **Вывод буферизуется целиком** — `remote_runtime/ssh.py:259-267`, `tool_providers/runtime_tools.py:111-121`, `sessions/runtime.py:101-109`. `capture_output=True` читает весь вывод в память, `max_output_bytes` применяется после. `cat` большого файла занимает память backend. Риск средний.
