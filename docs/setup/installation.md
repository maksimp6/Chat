# Установка системы Logos

## Системные требования

- Python 3 и зависимости из `requirements.txt`.
- Git и доступ к зависимостям из `requirements.txt`.
- Для ответов модели — Ollama на ПК владельца.
- Хранилище: нативный Kristall journal (`LOGOS_MEMORY_PATH`); SQLite и PostgreSQL выведены из эксплуатации, см. [docs/database.md](../database.md).

Android/Termux — один из вариантов запуска, а не обязательная платформа.
Путь к checkout выбирается пользователем; команды ниже выполняются из корня репозитория.

## Установка зависимостей

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example core/.env
```

Копирование шаблона выполняйте только при первой настройке, если собственного
`core/.env` ещё нет. `core/env.py` загружает именно этот файл.
Шаблон содержит примеры и заглушки, а не рабочую конфигурацию всех интеграций.

Перед запуском отредактируйте локальный `core/.env`:

- Для локального доступа задайте `HOST=127.0.0.1` и `PORT=8080`.
- Задайте собственное постоянное значение `LOGOS_PROVIDER_CREDENTIAL_KEY`
  до сохранения ключей провайдера. Его нужно сохранять вместе с резервной
  копией конфигурации: смена значения делает зашифрованные записи нечитаемыми.
  Для совместимости с Key Manager используйте ключ формата Fernet.
- Уберите незаполненные примеры необязательных интеграций. Не используйте
  строки вида `<...>` в качестве настоящих ключей и токенов.

## Запуск

```bash
python app.py
```

Откройте `http://127.0.0.1:8080`.

Порт задаёт переменная окружения `PORT`: в `.env.example` это `8080`,
а без переменной `app.py` использует `5000`.

`start.sh` создаёт `logs/` и запускает `python3 app.py`, но проверяет только
`requests` и `websockets`. Поэтому он не заменяет установку
`requirements.txt`, где также находятся `python-dotenv` и `cryptography`.

## Подключение к Ollama

Чат и эмбеддинги работают через Ollama на ПК владельца. Телефон обращается к ней
по домашней сети. Адрес сервера, модели, контекст и инструменты постоянны и заданы
в [`ollama_client/settings.py`](../../ollama_client/settings.py): вводить в интерфейсе
ничего не нужно. Значения и текущее состояние сервера показывает вкладка Ollama
в ⚙️ (`GET /api/ollama/settings`).

Пока Ollama на ПК не запущена, чат отвечает: «Локальная модель не ответила:
проверьте, что Ollama запущена на ПК.»

## Данные

Локально `storage/records.py` использует нативный журнал относительно рабочего каталога:
без значения по умолчанию; `LOGOS_DB_PATH` задаёт его имя, `LOGOS_MEMORY_PATH` —
точный путь. Файл `logos_pro.db` — legacy SQLite-данные: runtime его не открывает и не проверяет его наличие
(см. [docs/database.md](../database.md)).
SQLite backend выведен из эксплуатации. PostgreSQL backend выведен из эксплуатации (#1191): дополнительные зависимости
не нужны, `LOGOS_DATABASE_URL` не используется.

## Проверка работоспособности

```bash
curl --fail --silent --show-error http://127.0.0.1:8080/healthz
```

Ожидается HTTP 200 и JSON `{"status":"ok"}`.
Это проверка доступности веб-сервера, а не успешного ответа модели или MCP.
Отдельно проверьте загрузку интерфейса и ответ в чате.
