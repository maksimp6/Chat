# Установка системы Alice Pro

## Системные требования

- Python: текущий backend CI использует 3.14; конфигурация Ruff ориентируется на 3.12.
- Git и доступ к зависимостям из `requirements.txt`.
- Для ответов модели — доступ к Yandex AI Studio и настроенная запись провайдера.
- SQLite используется по умолчанию; PostgreSQL подключается отдельно.

Android/Termux — один из вариантов запуска, а не обязательная платформа.
Путь к checkout выбирается пользователем; команды ниже выполняются из корня репозитория.

## Установка зависимостей

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Копирование шаблона выполняйте только при первой настройке, если собственного
`.env` ещё нет. `config.py` загружает этот файл из корня репозитория.
Шаблон содержит примеры и заглушки, а не рабочую конфигурацию всех интеграций.

Перед запуском отредактируйте локальный `.env`:

- Для локального доступа задайте `HOST=127.0.0.1` и `PORT=8080`.
- Задайте собственное постоянное значение `ALICE_PROVIDER_CREDENTIAL_KEY`
  до сохранения ключей провайдера. Его нужно сохранять вместе с резервной
  копией конфигурации: смена значения делает зашифрованные записи нечитаемыми.
  Для совместимости с Key Manager используйте ключ формата Fernet.
- Уберите незаполненные примеры необязательных интеграций. Не используйте
  строки вида `<...>` в качестве настоящих ключей и токенов.

## Запуск

```bash
python app.py
```

Откройте `http://127.0.0.1:8080`.

Порт задаёт переменная окружения `PORT`: в `.env.example` это `8080`,
а без переменной `app.py` использует `5000`.
Значение `config.PORT` само по себе не управляет этим entrypoint.

`start.sh` создаёт `logs/` и запускает `python3 app.py`, но проверяет только
`flask`, `requests` и `websockets`. Поэтому он не заменяет установку
`requirements.txt`, где также находятся `python-dotenv` и `cryptography`.

## Подключение Yandex AI Studio

В локальном интерфейсе откройте «Провайдеры», введите **Yandex Cloud API key**
и **Yandex Cloud Project ID**, затем нажмите «Подключить».
Оба поля обязательны вместе. Backend проверяет ключ у провайдера, затем
сохраняет запись в `provider_credentials`.

Текущий runtime получает API key и Project ID из активной записи БД.
Одних `YANDEX_API_KEY` / `YANDEX_PROJECT_ID` в окружении, несмотря на их
наличие в шаблоне, для веб-чата недостаточно. Редактировать `config.py`
для записи ключа не требуется. Yandex-запрос также требует настроенного
`ALICE_PROVIDER_CREDENTIAL_KEY`.

Для постоянной эксплуатации учитывайте срок записи ключа и отдельный worker
ротации: [жизненный цикл ключей](../provider-key-rotation.md).
Запуск Flask сам по себе не означает, что worker запущен.

## Данные

Локально `db.py` использует `alice_pro.db` относительно рабочего каталога;
путь можно задать через `ALICE_DB_PATH`.
Для PostgreSQL установите дополнительные зависимости и настройте
`ALICE_DATABASE_URL` перед запуском:

```bash
python -m pip install -r requirements-postgres.txt
```

Выбор backend не означает переноса существующих данных.
Полнота PostgreSQL-совместимости отслеживается в
[#442](https://github.com/maksimp6/Chat/issues/442).

## Проверка работоспособности

```bash
curl --fail --silent --show-error http://127.0.0.1:8080/healthz
```

Ожидается HTTP 200 и JSON `{"status":"ok"}`.
Это проверка доступности Flask, а не успешного ответа модели или MCP.
Отдельно проверьте загрузку интерфейса, подключение провайдера и ответ в чате.
