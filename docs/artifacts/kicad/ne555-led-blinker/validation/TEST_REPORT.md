# Проверка NE555 LED Blinker

Дата: 2026-10-09 UTC. Проверена схема из PR #1071 на исходном head
`656157d1a0321831cc426dd65d90ba4d514adcc8`; сама схема и проект не изменены.
Среда: Python 3, KiCad CLI 9.0.2, стандартные библиотеки символов KiCad.

## Результат

- **17 тестов прошли, 0 пропущено** при доступном KiCad.
- Свежий ERC: **0 ошибок, 0 предупреждений, 0 исключённых нарушений**.
- Отдельно проверен режим без KiCad: **13 прошли, 4 явно пропущены**.
- 10 компонентов, 26 выводов, 7 цепей. Проверены все цепи целиком, включая отсутствие
  неожиданных соединений/замыканий: питание, земля, RESET, заряд/разряд, TRIG/THR,
  фильтр CONT, выход, последовательный резистор и полярность LED.
- Проверены 7 номиналов R/C, тип NE555P/DIP-8 и полярные C2/C3.
- Расчёт выполняется по номиналам, прочитанным из настоящего экспорта KiCad.
  Это не проверка только заранее записанной формулы с константами.
- Сохранённый netlist и ERC связаны SHA-256 с текущими `.kicad_sch` и `.kicad_pro`.
  При изменении входов Python-проверка требует нового экспорта и ERC.

Полные журналы: [с KiCad](tests-live.txt), [без KiCad](tests-without-kicad.txt).

## Отрицательные проверки

Изменения делаются только во временных копиях; исходная схема остаётся целой.

1. В копии редактируемой схемы метка питания RESET заменена с `+5V` на
   `RESET_DISCONNECTED`. Повторный экспорт KiCad и проверка цепей обнаружили
   разрыв связи U1.4 с питанием.
2. В копии схемы R2 изменён с 68 кОм на 6,8 кОм. Повторный экспорт и проверка
   номиналов обнаружили ошибку. Расчётная частота такой копии выше 6 Гц.
3. В копиях экспортированного netlist независимо проверены удаление соединения
   RESET, переполюсовка LED и изменение R2: все три дефекта обнаружены.

## Номинальные параметры

Источник формул: [Texas Instruments NE555, Rev. K, раздел 6.3.2, стр. 12](https://www.ti.com/lit/ds/symlink/ne555.pdf).
Использован `ln(2)`, а не округлённое 0,693.

- R1 = 10 кОм, R2 = 68 кОм, C3 = 10 мкФ
- Высокий уровень OUT / LED включён: **0,540655 с**
- Низкий уровень OUT / LED выключен: **0,471340 с**
- Период: **1,011995 с**
- Частота: **0,988147 Гц**
- Заполнение высокого уровня: **53,4247%**

При идеальных 5 В и даже замкнутом LED резистор R3 = 1 кОм ограничивает ток
до 5 мА, а мощность на нём до 25 мВт. Это консервативная верхняя граница,
не измеренный ток LED и не модель выходного каскада NE555.

## Повторение

Из корня репозитория:

```sh
python -m unittest tests.test_kicad_ne555_demo -v
```

Достаточна стандартная библиотека Python. Тесты также собираются штатным pytest.
Без `kicad-cli` 4 live-проверки явно пропускаются; сохранённые данные и связь
с исходниками всё равно проверяются. Для полного прогона нужны KiCad 9+ и
стандартные библиотеки символов. Проверенный маршрут настройки — Linux/XDG;
если библиотеки установлены нестандартно, задайте `KICAD_TEST_SYMBOL_DIR`.
Временная конфигурация тестов не меняет пользовательские настройки KiCad.

После разрешённого изменения схемы обновить доказательства и повторить тесты:

```sh
python tests/test_kicad_ne555_demo.py --refresh-evidence
python -m unittest tests.test_kicad_ne555_demo -v
```

Обновление прекращается при неправильных цепях/номиналах или нарушениях ERC;
ожидаемые значения тестов меняются только при намеренном изменении спецификации.
Netlist нормализован только для удаления абсолютного пути источника и отступов.
ERC запускается с `--severity-all --exit-code-violations`, без подавления правил.

## Ограничения

SPICE-переходный процесс не запускался: исполняемый `ngspice` отсутствует,
найдена только shared library; проверенная модель именно NE555P производителя
для этого проекта не получена. Модель CMOS TLC555 или идеализированная модель
не подставлялась. Расчёт RC не является SPICE-симуляцией.

Физический макет не собирался, осциллографом ничего не измерялось. ERC и эти
тесты не доказывают фактический запуск, уровень OUT под нагрузкой, яркость LED,
температурную стабильность или соответствие посадочных мест купленным деталям.
Допуски R/C, утечки электролита, реальное питание и параметры микросхемы меняют
частоту. Первый импульс после включения отличается от установившегося режима.

Это отдельная проверка схемы. Полный backend/Android suite локально не запускался;
статус обязательных проверок репозитория относится к точному опубликованному head PR.
