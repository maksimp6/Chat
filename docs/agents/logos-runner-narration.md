# Рассказ Логоса о запуске

`python -m scripts.logos_narration` читает уже сохранённый `result.json` раннера.
Дополнительная языковая модель не вызывается. Сначала идёт рассказ от первого
лица по машинному статусу, затем явно отделённый текст ответа модели. Это
итоговый рассказ по квитанции, а не потоковая озвучка во время исполнения.
Статус файла, результат модели и приёмка владельца различаются. Имена файлов,
аргументы инструментов, исходный Issue и сырые ошибки в рассказ не копируются.
Известные bootstrap-секреты и распространённые формы credentials удаляются из
цитаты до ограничения длины. Это не универсальный классификатор секретов.

## Выходные файлы

- `story.txt`: рассказ, до 2500 символов; сокращение объявляется в самом тексте.
- `receipt.json`: SHA-256 источника/текста, статус аудио, число попыток TTS,
  порядок частей и их SHA-256. Стоимость остаётся неизвестной, доставка и
  прослушивание — неподтверждёнными.
- `speech-001.ogg` и следующие части: только после явного включения синтеза.
  Слушать последовательно; каждая часть — отдельный OggOpus файл, их нельзя
  считать одним непрерывным аудиофайлом. При частичном сбое квитанция остаётся
  failed, даже если предыдущие части сохранились.

Каталог должен быть новым. Исходный `result.json` не изменяется. HTTP 200
недостаточно: проверяется заголовок Ogg/Opus; декодирование и фактическое
воспроизведение этим не доказываются. Автоповторов нет, максимум три запроса
на рассказ, до 1000 символов на часть, до 15 000 байт URL-encoded form.

## Раннер

Workflow `Logos` сохраняет отдельный artifact `logos-narration-RUN-ATTEMPT`
после основной работы и публикации PR, включая неуспешный запуск. Ссылка
попадает в итоговый комментарий. Сбой озвучки записывается отдельно и не
изменяет результат модели. Артефакт доступен через GitHub с обычными правами
доступа к Actions. Публикация артефакта не доказывает открытие на Android.

Ручной workflow `logos` (`logos-once.yml`) сохраняет **единственный шаг logos**.
Его wrapper добавляет рассказ в job summary, а квитанцию и аудиобайты — в
поле `narration` итогового JSON, доставляемого существующими
`LOGOS_RESULT_PART`/`LOGOS_RESULT_SHA256` log chunks. Для восстановления нужно
склеить и декодировать внешние base64-части, затем декодировать `audio_base64`
каждой `narration.parts` и сверить SHA-256. Это сохранение байтов в журнале,
не готовый аудиоплеер и не доказанная доставка на телефон. Дополнительного
artifact step в этом workflow нет. Ограничение части — 2 MiB; при сбое
озвучки исходные статус и exit code модели сохраняются.

По умолчанию сохраняется только текст. Для платного синтеза владелец отдельно
разрешает расход и настраивает `LOGOS_TTS_ALLOWED=true` и
`LOGOS_TTS_MAX_CHARS` от 500 до 2500. Это лимит символов на запуск, **не денежный
потолок**; фактическая стоимость неизвестна до данных провайдера. Настройка
включает TTS для последующих разрешённых запусков workflow; до такого решения
эти переменные менять нельзя. Отсутствие/невалидность лимита не разрешает TTS.
Ключ `YANDEX_API_KEY` должен иметь право SpeechKit TTS. Ключи, доступы и D0
данным изменением не создаются и не меняются.

Синтез использует обязательный `api.yandex_transport.yandex_request` из PR
#1569. До интеграции этой зависимости текст работает, TTS завершится ошибкой
ImportError без отправки; обходного HTTP-клиента нет. Для service-account API
key `folderId` не передаётся. Локальный запуск также поддерживает IAM token;
`YANDEX_FOLDER_ID`/`YANDEX_PROJECT_ID` передаются только в этой ветке.

```bash
python -m scripts.logos_narration --result /path/result.json --out /new/story
# Только после отдельного разрешения расхода:
python -m scripts.logos_narration --result /path/result.json --out /new/audio \
  --synthesize --max-chars 2500 --voice filipp
```

Официальный контракт: [SpeechKit TTS API v1](https://aistudio.yandex.ru/ru/docs/speechkit/tts/request),
сверен 24.10.2026. Приёмка продукта требует настоящего синтеза, проверки
декодирования, доставки и прослушивания на целевом устройстве.
