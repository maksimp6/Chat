# Роли и типы агентов

В системе Alice Pro используются специализированные AI‑агенты, каждый из которых выполняет чётко определённые функции.

## Типы агентов

### 1. CLI‑агент (`cli_agent.py`)

**Назначение:** взаимодействие через командную строку.

**Основные функции:**
* выполнение текстовых команд;
* запуск MCP‑инструментов;
* работа с файловой системой;
* выполнение Git‑операций;
* генерация отчётов.

**Особенности:**
* запускается отдельно от веб‑интерфейса;
* поддерживает пакетную обработку команд;
* логирует все действия в `logs/cli.txt`.

### 2. Чат‑агент

**Назначение:** обработка пользовательских сообщений в веб‑интерфейсе.

**Основные функции:**
* анализ входящих сообщений из `chat.js`;
* взаимодействие с Yandex AI Studio для генерации ответов;
* форматирование ответов с поддержкой Markdown (заголовки, маркированные списки, кодовые блоки);
* сохранение истории диалога в SQLite;
* логирование в `chat.txt`.

**Особенности обработки Markdown:**
* распознаёт заголовки (`#`, `##` и т. д.);
* обрабатывает маркированные списки (`-`, `*`);
* преобразует блоки кода (```...```) в `<pre><code>...</code></pre>`;
* **ограничение:** не поддерживает нумерованные списки.

### 3. Голосовой агент

**Назначение:** работа с голосовыми командами и ответами.

**Основные функции:**
* распознавание речи (через Android‑микрофон);
* синтез речи для голосовых ответов;
* интеграция с `voice.js` во фронтенде;
* логирование в `voice.txt`.

### 4. MCP‑агент

**Назначение:** управление MCP‑инструментами и выполнение системных операций.

**Основные функции:**
* запуск MCP‑инструментов (файловые операции, Git и др.);
* координация между инструментами;
* мониторинг выполнения задач;
* логирование в `api_debug.txt` и специализированные лог‑файлы.

**Поддерживаемые инструменты:**
* файловая система (`filesystem_mcp_tools.py`);
* Git (`git_mcp_tools.py`);
* архивация (`archiver.py`);
* профайлинг (`profiler_tools.py`).

### 5. Агент поиска

**Назначение:** обработка запросов поиска по данным системы.

**Основные функции:**
* поиск по содержимому файлов;
* поиск по истории чатов;
* поиск по системным логам;
* логирование запросов в `search.txt`.

## Взаимодействие агентов

Агенты взаимодействуют через общую систему сообщений и разделяемое хранилище данных:

1. **Обмен сообщениями:**
   * через общую очередь сообщений в SQLite;
   * с использованием стандартных форматов данных.

2. **Разделяемые ресурсы:**
   * база данных SQLite (`db.py`) — для хранения данных и состояния;
   * файловая система — для обмена файлами и векторными данными;
   * лог‑файлы (`logs/`) — для мониторинга и отладки.

3. **Координация:**
   * MCP‑агент выступает координатором для других агентов;
   * чат‑агент и голосовой агент могут делегировать задачи MCP‑агенту;
   * все агенты могут запрашивать информацию у агента поиска.

## Конфигурация агентов

Настройки агентов задаются в `config.py`:

* **API‑ключи** для Yandex AI Studio;
* **пути** к рабочим директориям;
* **ограничения** на выполнение операций;
* **уровни логирования** для каждого агента.

## Мониторинг и отладка

Для мониторинга работы агентов используйте соответствующие лог‑файлы:

| Агент | Лог‑файл | Что отслеживать |
|-------|----------|----------------|
| Чат‑агент | `chat.txt` | Обработка сообщений, ошибки Markdown |
| Голосовой агент | `voice.txt` | Распознавание речи, ошибки микрофона |
| MCP‑агент | `api_debug.txt` | Выполнение инструментов, ошибки API |
| Агент поиска | `search.txt` | Запросы поиска, результаты |
| CLI‑агент | `cli.txt` | Командные операции, ошибки выполнения |

## Рекомендации по использованию

1. **Для разработчиков:**
   * используйте MCP‑агент для автоматизации системных задач;
   * расширяйте функционал чат‑агента через новые промпты;
   * добавляйте новые инструменты в MCP для расширения возможностей.

2. **Для пользователей:**
   * используйте чат‑интерфейс для повседневных задач;
   * переключайтесь на CLI‑агент для пакетной обработки;
   * используйте голосовой агент для быстрого взаимодействия.

3. **Для администраторов:**
   * настраивайте права доступа агентов в `config.py`;
   * отслеживайте нагрузку через `stats.txt`;
   * регулярно проверяйте лог‑файлы на наличие ошибок.
