# Роли вокруг одного интеллекта (черновик)

Владелец, 08.11.2026: «есть интеллект, а системы нет: работников, суда,
полиции, цензоров, критиков». Этот документ — черновик такой системы. Он
продолжает эскиз пакетного цикла ([logos-batch-loop.md](logos-batch-loop.md))
и опирается на процедуру Суда ([logos-court-procedure.md](logos-court-procedure.md)).
Решения, которые остаются за владельцем, собраны в конце.

## Исходное положение

- **Интеллект один.** Сервер модели — asmrun на ПК без ОС; в памяти одна
  чат-модель за раз (9B в Q4_K_M) и эмбеддер. Смена чат-модели — около минуты.
  Контекст один с загрузки. Инструментов у раннера нет: он отдаёт модели
  инструменты, которые пришли в запросе, и возвращает вызов Логосу.
- **Инструменты — Логоса.** Реестр категорий (filesystem, git, python,
  remember, rootagent, …), исполнение и проверка вызова — в Логосе.
- **Суд уже есть.** Карточка эпизода, решение владельца; каждый ответ уже
  несёт вердикт Суда (`court.verdict`, `court.censored`).
- **Память — векторная база.** Каждый ход, факт, документ, результат
  инструмента записывается и в эмбеддинги (AGENTS.md); эмбеддер — тот же раннер.

Отсюда главное правило системы: **роль — это не отдельный агент, а смена.**
Роль = модель + системный промпт + набор инструментов + бюджет. Роли работают
по очереди на одном раннере, Логос переключает их, владелец — над всеми.

## Роли

| Роль | Что делает | Модель (предложение) | Инструменты | Пишет |
| --- | --- | --- | --- | --- |
| **Работник** | Выполняет задачу из очереди: читает, правит, коммитит, зовёт инструменты | `qwen35-9b-opus-distill` (Q4) | filesystem, git, python, remember | результат: дифф, коммиты, текст, вызовы |
| **Критик** | Разбирает результат работника до Суда: соответствует ли поручению, что сломано, чего не хватает | `qwen38-9b-reasoning` или второй экземпляр той же 9B с другим промптом | только чтение: read_file, grep_search, git_diff, git_log | рецензия: находки, предложение вердикта |
| **Цензор** | Проверяет текст и действия по правилам: AGENTS.md, секреты, запрещённые пути, маршрут публикации | `qwen35-0.8b-fast` + детерминированные правила без модели | нет | допуск / отказ с причиной |
| **Полиция** | Исполняет решения и останавливает нарушения: откат коммита, остановка задачи, блок инструмента | без модели: код Логоса | git (revert), управление очередью | акт исполнения |
| **Суд** | Карточка эпизода по процедуре; собирает рецензию критика, допуск цензора, акт полиции | без модели | нет | дело, `decision: ALLEGED` |
| **Владелец** | Решение по делу: принять, отклонить, вернуть с другой моделью | — | всё | `owner_acceptance` |

Цензор делится на две части нарочно: правила, которые можно проверить без
модели (файл вне разрешённых путей, push не в develop, force-push, секрет в
диффе, тесты запущены локально), проверяются кодом и не обсуждаются; модель
нужна только там, где правило требует понимания текста.

Полиция без модели: исполнение решений должно быть предсказуемым. Модель
может предложить откат, но откатывает код Логоса по решению владельца или по
детерминированному правилу.

## Конвейер одной задачи

```text
 очередь ──► Работник ──► Критик ──► Цензор ──► Суд (карточка) ──► Владелец
                │             │          │                             │
                │             │          └── отказ: задача в Суд сразу │
                │             └── рецензия в карточку                  │
                └── результат, trace, коммиты              Полиция ◄───┘
                                                   исполняет решение:
                                                   оставить / откатить /
                                                   вернуть в очередь
```

1. **Постановка.** Задача приходит из issue, из чата («в очередь: …») или из
   дела Суда. Запись в Kristall: `task_id`, источник, текст, цепочка ролей,
   модель каждой роли, инструменты, бюджет (ходов, токенов, минут), статус,
   `episode`.
2. **Смена работника.** Планировщик собирает пакет задач с одной моделью
   работника, просит раннер загрузить её, ведёт задачи по одной: системный
   промпт роли, инструменты роли, цикл ходов с вызовами. Между задачами —
   сброс контекста раннера (см. решения владельца). Всё, что работник
   произвёл, — в Kristall и в эмбеддинги.
3. **Смена критика.** Тот же пакет, модель критика: на вход поручение и
   результат (дифф, вывод инструментов, итоговый текст), на выход рецензия
   по фиксированной форме: что сделано, что не соответствует поручению,
   что сломано, что проверить, предложение вердикта. Критик не правит.
4. **Цензор.** Сначала правила кодом, затем, если нужно, модель. Отказ
   цензора не отменяет задачу, а отправляет её в Суд с пометкой.
5. **Суд.** Карточка эпизода по процедуре: источники (issue, SHA, trace,
   invocation), рецензия, допуск, `verification: NOT_RUN` (тесты только по
   отдельной команде на GitHub Runner), `decision: ALLEGED`. Отчёт пакета —
   один комментарий со списком карточек.
6. **Владелец** решает в Суде. **Полиция** исполняет: оставить, откатить
   (revert коммита, возврат файла), вернуть в очередь с другой моделью или
   другим поручением.

Автономная остановка без владельца разрешена полиции только по
детерминированным правилам цензора (push не в develop, секрет в диффе,
правка защищённого пути); всё остальное ждёт решения.

## Данные

```yaml
task:
  id: <uuid>
  source: {kind: issue|chat|court, ref: <#issue | conversation_id | episode>}
  text: <поручение>
  roles: [worker, critic, censor, court]     # цепочка смен
  models: {worker: asmrun-qwen35-9b, critic: asmrun-qwen38-9b}
  tools: {worker: [filesystem, git, python, remember], critic: [filesystem_read, git_read]}
  budget: {turns: 30, tokens: 60000, minutes: 40}
  status: queued|working|reviewing|censoring|in_court|done|failed|reverted
  episode: 1413/comment-<id>/<n>
review:
  task: <id>
  model: <ключ>
  done: <что сделано, по трассе>
  mismatches: [<расхождения с поручением>]
  broken: [<что сломано>]
  check: [<что проверить>]
  verdict_proposal: ALLEGED|OK|REJECT
censor:
  task: <id>
  rules: [{rule: <имя>, result: pass|fail, evidence: <...>}]
  model_notes: <или пусто>
  admitted: true|false
police:
  task: <id>
  decision: <из дела>
  action: keep|revert|requeue|stop
  evidence: <SHA отката, запись очереди>
```

Карточка Суда — существующая, без изменений; рецензия, допуск и акт
вкладываются в неё полями `sources` и `history`.

## Планировщик

- Пакет — задачи с одной моделью одной роли. Порядок смен: все работники
  пакета, затем критики, затем цензор и Суд. Смена модели — только на
  границе пакета (минута загрузки должна окупаться).
- Приоритет: чат владельца выше пакета. Если владелец пишет, пакет
  останавливается на границе задачи, модель чата возвращается.
- Раннер получает два маршрута: `POST /v1/model {"name"}` (выгрузка и
  загрузка чат-модели с флешки; эмбеддер остаётся) и `POST /v1/reset`
  (`q35_reset`, уже есть в коде).
- Окно очереди в интерфейсе Логоса: задача, роль сейчас, модель, статус,
  ссылка на эпизод. Окно только читает; действия — через чат.

## Что нужно написать

| Где | Что |
| --- | --- |
| research/asmrun | `POST /v1/model`, `POST /v1/reset` |
| Logos `batch/` (новый модуль) | очередь в Kristall, планировщик смен, прогон роли (промпт, инструменты роли, цикл ходов), запись всего в эмбеддинги |
| Logos `batch/roles/` | системные промпты ролей и формы: рецензия критика, правила цензора (код + модель), акты полиции |
| Logos `court/` | приём отчёта пакета, вложение рецензии/допуска/акта в карточку |
| Logos UI | окно очереди |
| Инструменты | профили по ролям в реестре (работник — полный набор категории, критик — только чтение) |

Порядок: сначала работник и Суд (очередь + карточка — это уже даёт пакет под
правилом Суда), потом критик, потом цензор-правила, потом полиция.

## Границы

- Одна модель в памяти: роли по сменам, параллельности нет.
- Все ходы, рецензии, допуски, акты — в Kristall и в векторной базе.
- Тесты кода не запускаются ни одной ролью; `verification: NOT_RUN`, пока
  владелец отдельно не поручит запуск на GitHub Runner.
- Маршрут публикации — прямой push в develop; роли его не меняют.

## Решения владельца

1. **Сброс контекста между задачами в пакете.** Правило чата — один контекст с
   загрузки. В пакете без сброса задачи видят друг друга. Предложение: сброс
   между задачами только в пакетном режиме.
2. **Форма инструментов для ролей.** Сейчас — одна функция на категорию с
   полем `tool` (правило AGENTS.md). Владелец назвал это лишним и хочет
   «имя функции и параметры». Плоская форма (одна функция на действие)
   требует переписать это правило.
3. **Модели ролей.** Предложены выше; на флешке есть ещё медицинская,
   математическая и агентная 9B для специальных пакетов.
4. **Границы полиции.** Что она вправе сделать без владельца, кроме
   остановки по детерминированным правилам.
5. **Доступ работника к телефону** (rootagent) — отдельная роль или часть
   работника; требует «глаз» (текстовый дамп экрана или VL-модель).
