# Структура интерфейса

Описание архитектуры фронтенд-части приложения: компоненты, маршрутизация, управление состоянием и взаимодействие с бэкендом.

## Локальные ресурсы

Все ресурсы веб-интерфейса Logos должны храниться в репозитории и загружаться по локальным путям. Это относится к JavaScript, CSS, шрифтам, иконкам, изображениям и отладочным библиотекам.

Не подключайте CDN, удалённые stylesheet/script URL или другие внешние asset URL в пользовательском интерфейсе. В частности, favicon должен загружаться из `/static/favicon.svg`.

Регрессионного теста для этого правила (`tests/test_local_web_assets.py`) в репозитории пока нет.

## Окно «Векторная база»

Плитка 🧬 «Векторная база» (`static/vectors.js`, действие `header.vectors.open`) открывает окно через `ui.modal.create`; название плитки и окна совпадает. Это не закреплённый диалог «🧬 База эмбеддингов».

- **Коллекции.** Окно читает `POST /api/vectors/collections` и показывает каждую коллекцию `vector_db`: число документов, частей и частей, которые найдёт поиск (`searchable` — части, встроенные текущей моделью документов `DOC_MODEL`). Если `searchable` меньше числа частей, строка говорит, что часть эмбеддингов сделана прежней моделью и поиском не находится.
- **Поиск по смыслу.** Поле поиска (как в окне «Логи», задержка 300 мс) отправляет `POST /api/vectors/search` с `query`, без `k` и без коллекции: сервер возвращает все совпадения по убыванию сходства. Окно показывает их по 50 строк, «Показать ещё» добавляет следующие 50 из уже полученного списка; запрос ничем не ограничен. Строка результата: коллекция, id документа, номер части, сходство и текст части. Статус: «Найдено: N из M частей». Пустой результат — не ошибка.
- **Только чтение.** В окне нет кнопок удаления, добавления и других изменений; поиск ничего не записывает. Окно не предлагается модели как инструмент.
