# Общая архитектура Alice Pro

Описание сверено с `master` на коммите
`de8f97c8342c8c073c84885bf8f301bba5692b33`. Статус интеграции и проверок находится
в [реестре](../integration/current-scope.md), а не определяется наличием схемы.

## Основной запрос

```text
Web UI / Android WebView / внешний MCP-клиент
    -> Flask и прикладные маршруты
    -> InvocationContext + ExecutionTrace
    -> вызовы модели и цикл инструментов
        -> Yandex AI Studio Responses API
        -> UniversalToolExecutor -> local/MCP-инструменты
    -> ответ, trace и расчёт внутренней стоимости
```

`InvocationContext` переносит идентичность и корреляцию выполнения.
`ExecutionTrace` объединяет запросы к провайдеру, ответы, инструменты, события,
ошибки, измерения времени и биллинг. Один пользовательский запрос может включать
несколько вызовов модели; это не повод создавать независимый trace для каждого
шага. Подробности: [trace и биллинг](execution_trace.md).

## Окружения внутри одного host

```text
Один процесс Alice Pro
    -> EnvironmentManager: создание, запуск, остановка, удаление
    -> RuntimeLoader: ограниченная точка входа выбранного коммита
    -> RuntimeDispatcher: owner, runtime scope, доступ к ресурсам
        -> RuntimeContext A + управляемый поток
        -> RuntimeContext B + управляемый поток
```

Это отдельный от пользовательского диалога уровень инфраструктуры.
`Environment` не заменяет `Conversation`, `Session` или `InvocationContext`.
Принятые границы исполнения описаны в
[контракте диспетчера](../runtime/runtime-dispatcher-policy.md).

Каждое окружение связывается с точным коммитом и собственным каталогом данных.
Новый коммит ветки не должен менять уже созданное окружение. Между gateway и
runtime нет отдельного localhost HTTP-сервера или контейнера на каждое preview.

**Ограничение текущего HTTP-пути:** gateway исполняет запрос через приложение
host; загрузка `alice_runtime.py` и операция `revision.invoke` сами по себе не
означают, что HTML, API и все статические файлы обслуживаются кодом выбранной
ветки. Проверка `healthz` не доказывает полноценное revision-specific приложение.
См. [потоковый host](../runtime/threaded-environment-host.md).

Потоки разделяют один интерпретатор и не являются защитной песочницей для
враждебного Python-кода. Разграничение runtime предотвращает нарушения принятого
контракта, но не заменяет изоляцию недоверенного кода.

## Владельцы ответственности

| Область | Точки реализации | Граница |
| --- | --- | --- |
| HTTP и конфигурация | `app.py`, `config.py`, модули маршрутов | Проверка входа и серверные настройки |
| Контекст и наблюдаемость | `invocation_context.py`, `trace_manager.py`, `trace_security.py` | Идентичность, корреляция и безопасное представление данных |
| Инструменты | `universal_tool_platform.py`, `tool_registry.py` | Единая проверка политик и исполнение local/MCP-вызовов |
| Окружения | `environment_manager.py`, `environment_routes.py`, `runtime/` | Жизненный цикл, ограниченная загрузка и runtime scope |
| Данные | `db.py`, `db_backend.py`, `storage.py` | Хранение и адаптеры, без неявного смешения runtime |
| Стоимость | `billing.py`, `treasury.py` | Расчёт отдельно от проведения расхода |
| Клиент | `templates/`, `static/`, `android/` | Интерфейс, локальные ресурсы и WebView |

Агенты диалогов, плагины и storage-адаптеры должны использовать эти границы, а не
создавать свои независимые диспетчеры, системы прав и параллельные trace.

## Хранение

SQLite остаётся стандартным backend для локального запуска и Termux.
PostgreSQL включается явно через `ALICE_DATABASE_URL`; это не обязательное
условие локального запуска. Runtime-окружения используют собственную SQLite в
каталоге данных и не должны неявно наследовать production-базу host.

Supabase trace mirror является отдельной диагностической интеграцией. Ошибка
зеркалирования не должна прерывать основной запрос; наличие mirror не означает
переключение основной БД на Supabase. См. [описание БД](../database.md).

## Фронтенд и проверка

Основной клиент использует HTML, CSS и JavaScript. Принятый подход к проверке
поведения: BrowserShim/VM и HTTP-контракты без обязательного Chromium/Playwright.
Ресурсы интерфейса хранятся в репозитории. Ошибка необязательного модуля не должна
блокировать базовый интерфейс.

Это требования к развитию, не утверждение, что все существующие проверки уже
проходят. Реальные регрессии и оставшиеся расхождения CI перечислены в реестре.
